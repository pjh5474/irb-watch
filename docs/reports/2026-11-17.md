- **Test lesson (so nobody reruns the same file in a loop):** once the suite had 9 test files, one file silently never ran each time. The log said "Worker exited unexpectedly during started state" and the file's tests were missing from the totals. **Cause:** the test pool has 8 workers (8 CPUs) and reuses a finished worker for the 9th file, which then exits. It follows the file, not the code: renaming the file moved the crash. **Fix:** `maxWorkers: 16` in `vitest.config.mts`; 6 of 6 runs then passed with all 9 files. **Rule:** keep `maxWorkers` above the number of files in `test/`, and compare the summary's file count with `ls test/*.spec.ts`. Wrong guesses I tried first: a 51 MB test allocation, the remote AI binding, running files one after another (that made it much worse). Written down in the repo's `CLAUDE.md`, `docs/runbook.md` and `docs/plan.md`.
