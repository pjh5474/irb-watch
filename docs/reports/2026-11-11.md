## Decisions made today
- **SaaS-ready rule** (added to CLAUDE.md):
  - new tables are shaped so an organization id can be added;
  - data access stays behind the `db/` stores;
  - slow work runs as jobs;
  - usage is recorded per user and action;
  - hospital specifics stay out of the core.
- **The stack stays** FastAPI, Supabase and Next.js.
- **Organizations:**
  - one per user, for registering users and statistics only;
  - they never grant access;
  - managed by platform admins only;
  - soft delete, refused while users remain;
  - statistics by calendar month in Seoul time;
  - usage counts where it happened.
- **Private sources stay per user:** access to a members-only, R-BAY or manual source is given by the platform admin to each user. An organization that wants a login site asks the admin, who registers it with that organization's hospital login.
- **Users tab:** the temporary password is typed by the admin.
- **IRB pipeline:**
  - **Scope:** one per study per hospital inside a project; owner only for now.
  - **Steps:** the default types and order are set by the admin, globally and per hospital; users may add steps.
  - **Per-step AI settings:** instructions, guides and form, input rules, and a checklist.
  - **Inputs:** documents are chosen now; vector search comes later.
  - **Drafts:** standalone drafts stay; drafts in steps run as background jobs (phase 3).
  - **Reminders:** due dates with a reminder mail (phase 4).
  - **Documents:** uploads are versioned by name; only a whole document can be removed (soft, 30 days).
  - **Statuses and dates:** the default status set is editable by the admin; dates are auto-filled and editable.
  - **Start:** a button per hospital.
  - **A hospital that leaves the project:** its pipeline is kept.

## Problems found and fixed (mostly mine)
- **Two code reviews found real bugs, all fixed:**
  - **Form templates (10 findings):** among them, a replaced file losing the admin's field check, an answer containing `{{x}}` being treated as a marker, and the purge's file list.
  - **Pipeline phase 2 (9 findings):**
    - a `RESTRICT` key that could block deleting a user;
    - purge failures orphaning files;
    - uploads read whole before their size check;
    - an upload race giving a bare 500;
    - a step reorder that could half-apply;
    - restoring a step past the 60-step limit;
    - the upload answer missing its new version;
    - an access check making 2 extra queries per hospital.
- **A name clash:** a service method named `list` broke the type hints written after it.
- **A "Saved" message vanished** because the step-type editor closed after saving.
- **Help text hid form fields from screen readers:** hints inside `<label>` made the labels unreadable to screen readers and to tests; the hints now sit outside the label.
- **History labels:** message keys with dots are not allowed by the translation library.
- **A timestamp sent as text:** I wrote `"now()"` as a timestamp string once; it was caught before any test ran.
- **Wrong expectations in my own tests**, not in the code: a restored step's position, and a too-short DOCX test file.
- **One full backend run showed a single failure** that I could not identify or reproduce; every run since has passed.
